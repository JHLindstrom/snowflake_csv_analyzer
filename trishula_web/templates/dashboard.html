Localhost support model: Trishula is designed for one trusted user on the same workstation. Keep the server bound to 127.0.0.1.

Quick start

  1. Select a CSV or Parquet file with Upload CSV/Parquet.
  2. Confirm the active filename, managed size, and free disk space.
  3. Review Executive KPIs, then build an ordered funnel or inspect transitions.
  4. Use Sankey Flow to compare the strongest event-to-event movements by volume.
  5. Use Session Explorer for exact event-token and contiguous-subpath searches.
  6. Export only the visible analysis with Export Selected Tab to PDF, or unload the dataset when finished.

Required dataset schema

ColumnPurposeExample
SESSIONSession identifierSESS_123
EVENT_PATHOrdered event sequenceHome->Search->Checkout
TOTAL_EVENTSNumeric session depth3

Supported path delimiters are ->, comma, >, and pipe. Detection samples the first non-empty paths; provide the delimiter explicitly in the CLI if detection is ambiguous.

Dedupe and funnel semantics

  • Consecutive: A→A→B becomes A→B.
  • Unique: retains the first occurrence of each event in source order.
  • None: analyzes the raw path.

Sequential funnels require each step to occur after the previous matched step. Intervening events are allowed, and repeated funnel steps such as A→B→A are supported.

Storage and safety

  • Browser uploads are streamed into generated filenames under uploads/.
  • Unload Dataset deletes the managed browser-upload files for the current session.
  • Custom SQL and restart require trusted-local mode.
  • Custom SQL is bounded by configured time and result-row limits and can be cancelled through the job API.

Useful commands

trishula run-all data.csv --funnel "Home,Search,Checkout"
trishula inspect data.csv --limit 5
trishula benchmark --rows 1000000 --output-dir ./benchmark-output
trishula-web --host 127.0.0.1 --port 8000

The repository README contains the full command reference, environment-variable reference, test instructions, and advanced security notes.

Troubleshooting

  • Missing columns: export or rename fields to the required uppercase schema.
  • Incorrect funnel counts: verify delimiter detection and selected dedupe mode.
  • Empty transition matrix: wait for calculation to finish, then check the displayed status. Sessions containing only one event legitimately have no transitions.
  • Out of memory: lower TRISHULA_DUCKDB_MEMORY_LIMIT and confirm sufficient temporary disk space.
  • High CPU usage: lower TRISHULA_DUCKDB_THREADS; the dataset banner shows the active thread and memory limits.
  • Slow analytics: tabs load on demand and heavy queries are serialized by default. Benchmark before increasing TRISHULA_DUCKDB_THREADS or TRISHULA_MAX_CONCURRENT_ANALYTICS.
  • Loading indicator remains visible: review its current stage and elapsed time. After ten seconds Trishula confirms that the operation is still active; large exports can legitimately take several minutes.
  • Upload rejected: check file extension, configured upload limit, and CSV/Parquet validity.
  • Trusted feature returns 403: restart with TRISHULA_TRUSTED_LOCAL_MODE=true only on a trusted workstation.
